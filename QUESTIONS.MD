# Контрольные вопросы

**1. Зачем добавлять папку PHP в переменную PATH и как проверить, что PHP установлен?**
Чтобы команда `php` запускалась из любого окна CMD без указания полного пути к `php.exe`. Проверка: открыть новое окно CMD и выполнить `php -v` (покажет версию) и `php --ini` (покажет, какой php.ini загружен).

**2. Какой командой запускается встроенный сервер PHP и как указать другой порт или корневую папку?**
`php -S localhost:8000` — запуск в текущей папке. Другой порт: `php -S localhost:8080`. Корневая папка: `php -S localhost:8000 -t C:\projects\filemanager`.

**3. Почему форма загрузки не работает без enctype="multipart/form-data"?**
Без этого атрибута браузер отправляет только текстовые поля (имя файла), а не его содержимое. Кодировка `multipart/form-data` разбивает запрос на части и позволяет передать бинарные данные файла, поэтому без неё `$_FILES` будет пустым.

**4. Какие ключи содержит массив $_FILES['userfile'] и что хранится в tmp_name?**
`name` (исходное имя), `full_path`, `type` (MIME-тип от браузера), `tmp_name`, `error` (код ошибки), `size` (размер в байтах). В `tmp_name` лежит путь к временному файлу на сервере, куда PHP сохранил загруженные данные; он удаляется после окончания скрипта.

**5. Чем move_uploaded_file() отличается от copy()?**
`move_uploaded_file()` проверяет, что файл действительно был загружен через HTTP POST, и перемещает его (а не копирует). `copy()` такой проверки не делает, так что через него можно подсунуть путь к чужому файлу на сервере.

**6. Чем отличаются директивы upload_max_filesize и post_max_size? Какое значение должно быть больше и почему?**
`upload_max_filesize` — предел размера одного файла, `post_max_size` — предел всего POST-запроса (все файлы + поля формы). `post_max_size` должен быть больше, потому что в запрос входят не только файлы, но и другие поля формы и служебные данные; при нескольких файлах он должен вмещать их суммарный размер.

**7. Что произойдёт с массивами $_POST и $_FILES, если запрос больше post_max_size?**
Оба массива окажутся полностью пустыми, а в журнале появится предупреждение. Код ошибки в `$_FILES` проверить не получится, поэтому превышение определяют по пустому `$_FILES` при `CONTENT_LENGTH > 0`.

**8. Почему upload_max_filesize нельзя изменить через ini_set()?**
К моменту запуска скрипта файл уже принят сервером и проверен по этому лимиту, так что менять его внутри скрипта поздно. Директиву задают в php.ini или ключом `-d` при запуске сервера.

**9. Для чего при удалении и сохранении файлов используется basename()?**
Она отбрасывает путь и оставляет только имя файла. Это защищает от обхода каталога: без неё, передав `?file=../index.php`, можно было бы удалить файл сайта, а при сохранении — записать файл за пределы папки uploads.

**10. Почему нельзя разрешать загрузку файлов с расширением .php?**
Загруженный `.php`-файл лежит на сервере и может быть запущен через браузер, то есть злоумышленник получит возможность выполнять на сервере произвольный код.
